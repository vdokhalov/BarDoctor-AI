# SALES v455 — исправление AUDIT-01 / AUDIT-02

Baseline production: v455, `6014b49c225b8a227e87b8a0b2462f0fd380cc94`. Production в этой задаче не изменяется.

## Поведение после исправления

**AUDIT-01.** При наличии самостоятельного проведённого импорта, не связанного с учтённой выручкой, месячный отчёт возвращает `UNLINKED_SALES_CONSUMPTION`. Себестоимость, валовая/операционная прибыль и переоценка остаются `null`, вместо достоверной на вид прибыли с пропущенным расходом.

Проверяются полностью и частично проведённые batches, а также расходные движения без сохранённого batch. Черновики, отменённые импорты, чужие заведения и другие месяцы не мешают текущему расчёту. Полностью сторнированные расходы исключаются по сохранённой истории. Если самостоятельный импорт отменён, полный расчёт автоматически восстанавливается. Выручка не создаётся из текущей цены меню, стоимость не суммируется вслепую: это могло бы удвоить уже отражённую продажу.

Проверенный пример: обычная продажа и самостоятельный складской импорт расходуют по 5 MDL. До исправления отчёт показывал прибыль 15 MDL и переоценку −5 MDL. Теперь он явно показывает неполное покрытие, а не присваивает непроверенным данным числовую прибыль. Полный согласованный контрольный сценарий по-прежнему даёт выручку 135, себестоимость 19 и прибыль 116 MDL.

**AUDIT-02.** `POST /api/sales-batches`, `action: reverse` для batch, связанного с подтверждённым дневным отчётом, возвращает HTTP 409 `SALES_BATCH_LINKED_CONFIRMED_REPORT` с объяснением причины. Остатки, движения, отчёт, выручка и audit log не меняются.

Хранилище документов включено в CAS-проверку: если связанный отчёт подтверждён конкурентно, операция повторно проверяет состояние и отклоняет опасную отмену. Обычная отмена самостоятельного импорта и полный возврат ручной продажи сохраняются. Возвраты POS не включались.

## Ограничения

Полная согласованная отмена подтверждённого дневного отчёта не реализована: опасная складская отмена теперь заблокирована. Для самостоятельного импорта без доказанной связи с учтённой выручкой отчёт намеренно показывает неполные финансовые данные. Это защита от ложной прибыли, а не автоматическое сопоставление импортов с чеками. Уже закрытые месячные snapshots остаются замороженными.
