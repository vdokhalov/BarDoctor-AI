Phase 4A — UNKNOWN cost → verified resolution

Цель / ценность: владелец замечает конкретную проблему, исправляет техкарту и видит проверенный durable before/after. Исправленная проблема не исчезает бесследно.

Scope: только активная explicit RECIPE позиция с отсутствующей/пустой/неподтверждённой обязательной картой; единая identity Home/Health, deterministic WHY/evidence, existing Tech Card/editor, authoritative source reread/CAS, verified result/history/recurrence. Текущий UX correction: первый единый компактный Health hero с canonical /100, scoped cost status/count, одним top signal и одним CTA; score→Health, signal→detail, CTA→correction. Большая Home AI card убрана; существующий глобальный вход сохранён. Backend lifecycle не расширяется.

Dependencies: Phase3A authority/RBAC/revisions, existing domain_data/CAS, source completeness, editor explicit Save. REUSE persistence, no migration/backfill.

Backend/frontend/tests: уже реализованный narrow cost adapter, только Home presentation/navigation correction в текущем изменении. Полный build/typecheck/lint/unit/contract/native Worker regression; repeated assembled artifact; actual390/820/1280 flow, shorter390×664 and keyboard430; Home/Health/Finance/Sales/Shifts/Stock/Purchases/Menu/Reviews/Tasks/venue switching/provenance сохранены.

Exit: automated gates, exact commit/assembled artifact/GitHub CI synchronized, два новых независимых owner UAT PASS за≤60 секунд orientation, отдельное owner deployment confirmation. Productionv483 до этого неизменна. Release BLOCKED; прежний ownerUAT1FAIL не переименовывается.

Phase 4B — comparable deterministic loops / broader follow-up

Цель / ценность: понять отклонение выручки и проверить результат управленческого действия на сопоставимых данных.

Scope: revenue loop следующим slice, типизированные сравнимые periods/shifts/baselines, canonical decomposition receipts×averageCheck без выдуманной причины; собственные missing/completeness/finality predicates, ranking и due follow-up/noise controls. Reuse 4A episodes/results и существующие Tasks/result-control; не новый Tasks engine. Приоритетно закрыть конкретные PARTIAL catalog contracts по таблице: sales/shift comparability, source coverage и margin/policy prerequisites. Подготовить reusable deterministic answer-query contracts/envelopes для 4C, не обещать глобальный AI UX в4B.

Dependencies: принятый4A, source-specific canonical coverage, venue timezone/opening exposure, captured historical sales/cost. Revenue fixture: isolated local QA, четыре одинаково экспонированные закрытые пятницы одной timezone/currency; последние две comparable windows, known receipts and total revenue; deterministic current/reference split. При missing/incomparable period → UNKNOWN, не false decline. Параметры/даты/expected values из Final Spec§15; фиктивные production операции запрещены.

Backend/frontend/tests: additive typed rules/comparable read contracts, existing job infrastructure если подтверждена; reuse Health/detail/domain links and Tasks. Fixtures normal/drop/missing/zero/open/incomparable/stale/retry; regression4A history/cost/editor plus three widths.

Exit: revenue detection→WHY/evidence→owner action→dated measurement verification на QA, честная correlation vs effect semantics, idempotent history и noise, source/RBAC isolation, accepted responsive/UAT. Curated entries не включаются лишь потому, что изменился phase number.

Phase 4C — curated/contextual AI Doctor

Цель / ценность: владелец выбирает полезный вопрос без написания prompt и получает проверяемый ответ по своему заведению.

Scope: versioned capability registry как typed product asset (stable shared IDs, original entry texts/aliases, context variants, required sources/permissions, period semantics, deterministic query handler, evidence and insufficient tests); structured answer payload; signal-bound contextual suggestions; existing global AI entry «AI Doctor — Что стоит разобрать?», recommended4–6 SUPPORTED only, все категории с отдельными Прибыль/Себестоимость. Optional interpretation + explicit uncertainty; material revision invalidates stale standalone analysis. Free-form deferred. Reputation facts/interpretation/topic coverage may follow as accepted sub-slice, not invented causality.

Dependencies: contract-ready rows in full mapping; per-capability gaps from4B/source work resolved before activation. Existing LLM/runtime is optional and receives validated facts only. Initial enabled set determined by utility+authority+testability, not fixed count. PARTIAL/NOT YET entries visible only as unavailable explanation if useful, never enabled capability.

Backend/frontend/tests: registry/permission-scoped query adapters + typed answers, fact/evidence validation and revision binding; reuse canonical calculator/resolver and existing Doctor entry. Contextual question UI within Health detail, global supported categories; no second center or generic chatbot. Tests exact arithmetic, missing/stale/conflict/changed revision/RBAC/multi-venue, denominators, aliases, recommendation rank/dedup, all facts traceable, optional AI cannot change figures/severity or close signal; 390/820/1280 regression.

Exit: every enabled question has deterministic tested handler and original evidence, explicit scope/period/freshness/limitations and valid next action. All numbers reconciled; FACT/INTERPRETATION/RECOMMENDATION/UNCERTAINTY visually distinct; UNKNOWN never fabricated. Signal context maintained. Curated global/contextual owner UAT accepted.

Phase 4D — group venue / calibration / deeper operational questions

Цель / ценность: видеть группу заведений без смешивания чужих данных и получать более зрелые operational checks.

Scope: cross-venue queue/grouping with venue-specific baselines, explicit aggregation semantics, calibrated noise/workload. Completeness-aware stock demand/ageing/consumption/reconciliation questions only after required anchors/retention/period contracts; inventory priority policy. Optional review↔operation descriptive association only if join/coverage validated; proof of causality is not promised. NOT YET question remains disabled until a defensible contract exists.

Dependencies:4A/B single-venue correctness;4C only for optional group reasoning. No implicit money/currency merge.

Backend/frontend/tests: scoped aggregate reads/pagination/live auth, existing venue picker/group lens, scope-preserving drilldown. Negative controls foreign venue/RBAC/revisions; heterogeneous currencies/periods; partial warehouse history; no theft allegation from anomaly; same three widths.

Exit: complete per-venue traceability, explicit partial aggregation/count semantics, calibrated ranking/noise and accepted owner group workflow; old episodes/results preserved.

Не строим: AskAnything, fake financial facts/evidence, autonomous AI actions, arbitrary new score, new Management Center, new Tasks engine, full alert migration or global visual redesign. Current4A release remains blocked;4B–4D are design, implementation not started.
