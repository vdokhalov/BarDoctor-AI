# Shift-owned sales accounting — local correction, 2026-10-20

Status: local only; no push/deploy authorized. Base v560 SHA6c49ff0ab3b0544220734720722b595a2377c954.

## Semantics
Existing revenue/cash-session rows own sales mode. A POS session keeps its POS source; a new manual session has a distinct id/shiftId, accountingScope=SHIFT, manualTotalsVersion=2 and immutable salesModeSnapshot=MANUAL. No new parallel module or database table. Existing workday remains a single daily operational/payroll container with multiple sales sessions.

Owner setting appends shiftChanges in existing sales-accounting store. It configures the next opened session, even today, without modifying an active session. Opening any next session remains blocked by open cash/manual sessions or orders. Manual session requires the same staffed open workday as POS and takes that workday's persisted business date (including overnight), not a fresh calendar date. Monthly lock and closed workday protect writes.

The manual page opens/selects a particular session and saves/closes its totals. Missing revenue/receipts/COGS remain null while open; explicit zero remains zero. Corrections have revisions, reasons, CAS, audit and operation IDs. Closing workday requires all sales sessions closed. Manual aggregate revenue cannot prove employee-level attribution; personal sales remain unknown unless explicitly supplied in the existing workday workflow. Venue-sales payroll uses combined daily revenue once.

## History / imports / pending settings
Historical version1 manual rows remain whole-day totals. They are visible read-only after adoption, not converted into sessions. New sessions cannot coexist with a historical daily total or imported daily report for the same date. Legacy venues retain their old setting until an explicit owner selection adopts the shift policy; the old dates stay in changes as historical evidence.

QA3390-like old future transition requires a visible unchecked confirmation and acceptLegacySchedule=true. The new audited change marks replacesLegacySchedule; the old changes are retained unchanged. No live migration was performed. A repeated old date-operation ID cannot silently adopt or alter the new policy.

Daily imports overlapping shift rows remain staged for coverage reconciliation. Existing whole-day replacement is limited to one version1 manual day; it cannot replace a version2 session, even if that is the only row. Standalone import posting cannot bypass the policy.

## Read models
POS300 + manual200 in distinct sessions = daily500. Shared operational-day projection recognizes MIXED_SHIFTS, verifies POS facts against the POS subset, includes open manual sessions in close blockers, preserves unknown receipts, and combines payments once. Manual declared costs contribute once per session, with daily-history overlap rejected. Current Finance records OWNER_DECLARED or MIXED cost basis. Existing daily payroll remains one recorded population, not copied per session. Shared client modules are regenerated by the production build.
