# BarDoctor Local Connector для Windows

Версия 1.1.0 — локальный агент только для чтения данных из файловой базы
1С:Предприятие. Первый профиль рассчитан на 1С:Предприятие 8.2 и
1С:Общепит 2.0.

## Поддерживаемые Windows

- Windows 10/11;
- Windows Server 2016 и новее;
- Windows Server 2012 R2 Standard/Datacenter — только при установленном
  .NET Framework 4.8, рабочем TLS 1.2 и действующих Microsoft Extended
  Security Updates со всеми актуальными исправлениями безопасности.

Поддержка Server 2012 R2 ограничена жизненным циклом Microsoft ESU до
13 октября 2026 года. После этой даты установщик блокирует новую установку:
использование неподдерживаемой ОС не считается безопасным production-режимом.

Не поддерживаются Windows Server 2012 без R2, Windows 8/8.1 и более старые ОС.

## Сначала проверьте совместимость

1. Полностью распакуйте ZIP в обычную папку.
2. Дважды нажмите `Check-BarDoctor-Compatibility.cmd`.
3. Дождитесь итоговой строки `ошибок 0`.
4. Для Server 2012 R2 передайте администратору предупреждение об ESU и
   попросите подтвердить, что сервер получает актуальные security updates.

При запуске installer на Server 2012 R2 это подтверждение запрашивается ещё
раз. Без явного подтверждения установка не продолжается. Проверка не пытается
угадывать состояние лицензии ESU по ненадёжному локальному признаку.

Проверка не открывает информационную базу и не читает файл базы. Она проверяет:

- версию Windows и PowerShell;
- .NET Framework 4.8 и встроенный x86 C# compiler;
- Windows DPAPI CurrentUser;
- доступ к локальной encrypted queue;
- per-user background startup;
- регистрацию 32-bit `V82.COMConnector`;
- реальное TLS 1.2 соединение с BarDoctor с обычной проверкой сертификата.

Результат сохраняется в `compatibility-report.txt`. Этот файл не содержит ключ
BarDoctor или пароль 1С.

## Установка без командной строки

1. Дважды нажмите `Install-BarDoctor-Local-Connector.cmd`.
2. Installer повторно и обязательно выполняет compatibility preflight до
   копирования файлов.
3. В открывшемся мастере вставьте ключ из BarDoctor.
4. Выберите найденную базу 1С и нажмите «Проверить подключение к 1С».
5. Нажмите «Синхронизировать сейчас».

Требуются .NET Framework 4.8 и установленная 32-bit платформа 1С 8.2 с
COM-соединением. Python, Node.js, npm, ручной запуск PowerShell и изменение
конфигурации 1С не нужны.

## Права администратора и фон

Connector устанавливается для текущего пользователя в LocalAppData, использует
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` и не устанавливает Windows
Service. Поэтому постоянные права администратора не требуются.

Администратор нужен только если на сервере отсутствуют .NET Framework 4.8,
обновления Windows/ESU, доверенные корневые сертификаты или компонент COM 1С.
Установка .NET/Windows updates может потребовать reboot. Сама установка
Connector reboot не требует.

После отключения RDP без выхода из Windows агент продолжает работать. После
logoff или reboot он запустится при следующем входе того же Windows-пользователя.
Для работы без входа пользователя понадобится отдельный Windows Service design;
он не включён в эту версию, потому что потребовал бы постоянной service identity
и другой модели DPAPI.

## Поток данных

`1C COM external connection -> OneCAdapter -> Sync Engine -> encrypted
local queue -> BarDoctor /api/integration/v1/ingest -> canonical Sync Engine`

Адаптер открывает базу только штатным `V82.COMConnector` и использует чтение
метаданных и запросы `ВЫБРАТЬ`. Он не открывает файл базы напрямую. В коде нет
вызовов записи, проведения, удаления, транзакций или изменения конфигурации.
Для дополнительной защиты рекомендуется отдельный пользователь 1С без прав
записи: COM-соединение получает права выбранного пользователя.

## Состав и безопасность

Установщик собирает проверенный C#-код встроенным x86 compiler .NET Framework,
устанавливает приложение для текущего пользователя, создаёт ярлыки и включает
per-user автозапуск.

Пакет пока не подписан цифровой подписью. Для подписанного MSI/EXE нужен
сертификат подписи кода и доверенный Windows build runner.

- настройки, пароль 1С, cursor и очередь: Windows DPAPI CurrentUser;
- журнал: ключи и пароли маскируются;
- transport: только HTTPS/TLS 1.2, без отключения certificate validation;
- cursor и fingerprints продвигаются только после принятого пакета;
- retry сохраняет исходный delivery ID и не создаёт дубли.

## Поддерживаемые данные

- номенклатура;
- поставщики;
- склады;
- проведённые приходные документы;
- остатки.

Продажи, сотрудники, техкарты, списания и возвраты в этой версии отключены.
